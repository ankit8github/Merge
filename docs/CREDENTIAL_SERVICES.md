## Interfaces and input contract

```python
service = CredentialService(engine)
identity = service.register(username=username, password=password, display_name=None)
identity = service.verify_credentials(username=username, password=password)
# immutable CredentialIdentity(user_id, username); never returns a password/hash
```

Only a SQLAlchemy Engine is accepted, never a caller Connection/Session. No user_id
or actor_id input exists. Registration always generates a fresh UUID, even if an
existing user's display name matches. A principal without credentials cannot be
claimed by knowing its UUID/name. No existing-user backfill or adoption occurs.

Canonical usernames are exactly 3–32 lowercase ASCII letters, digits/underscores;
uppercase, whitespace, Unicode and normalization shortcuts are rejected. Passwords
are 15–128 Python Unicode code points with valid UTF-8 encoding (at most 512 bytes),
including spaces/passphrases. No trim, truncation, normalization or composition
rules. Unpaired surrogates are rejected. Optional display name defaults to username;
otherwise it follows users' 1–80-character/non-space-only contract, with invalid
UTF-8/NUL rejected before SQL. No email verification/MFA/password-reset claims.

## Password work and secrets

Pinned argon2-cffi 25.1.0, bindings 26.1.0, cffi 2.1.1, pycparser 3.12. Lock resolution
preserved all existing package versions. Explicit Argon2id v19 parameters:

| Parameter | Value |
|---|---|
| memory_cost | 19456 KiB (19 MiB) |
| time_cost | 2 |
| parallelism | 1 |
| random salt | 16 bytes, generated by the library per hash |
| hash output | 32 bytes |
| concurrent expensive operations | 2 per process, shared across codec instances |

This meets the [OWASP minimum profile](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#argon2id).
Uses the maintained [argon2-cffi high-level API](https://argon2-cffi.readthedocs.io/en/stable/api.html).
The two-slot nonblocking semaphore covers hash, real verification and dummy
verification. Saturation returns hashing_busy immediately; no waiting queue or DB
locks while waiting. Nominal Argon2 working memory is 38 MiB per process plus
overhead. Multiple processes multiply this budget. It is resource admission,
not a durable login rate limiter or deployment sizing/load result.

The default codec creates one random dummy hash in memory during service module
initialization, before any username lookup. Unknown users receive the same-profile
verification work as wrong passwords. Missing/malformed/unsupported stored hashes
also fail closed through dummy verification. Verification accepts only this exact
bounded profile, salt/output lengths and Argon2id v19 encoding, preventing a stored
cost value from causing unbounded native allocation. Other profiles need an
explicitly reviewed compatibility/rehash policy. Existing hashes are never changed.
Random salts, database lookup, scheduling and infrastructure errors still affect
latency; this is not a claim of constant response time or statistical timing proof.
Invalid public syntax/length is rejected before lookup/expensive work, independently
of account existence.

No plaintext persistence, reversible encryption, hardcoded real passwords/hashes,
logging or secret-bearing result/error fields. Engine requires hide_parameters=True
and echo=False/None to avoid SQL parameters/debug-row logging. Caller-installed
event listeners, logging handlers, DB/server logging, APM and traceback-local
capture remain trusted deployment configuration: never enable secret capture.
Fixed-code errors detach native/DBAPI exception context; Python traceback frames
can still retain transient inputs until released. Python strings cannot be reliably
zeroized. Do not log locals, request bodies, encoded hashes or full database URLs.

## Transaction authority and error contract

Registration validates inputs, hashes **before acquiring a DB connection**, then
owns one connection/transaction for INSERT users + INSERT account_credentials.
There is no pre-check for username availability: uq_credentials_username decides
simultaneous registration. A loser rolls back its new user too. Return occurs only
after successful COMMIT. No partial commits, automatic retries or network calls
inside the transaction. Credentials are not sessions or authenticated HTTP actors.

Before any service SQL, both methods require synchronous PostgreSQL+psycopg,
actual connection.connection.dbapi_connection.autocommit **is False**, no active
caller transaction and actual READ COMMITTED. Missing/unreadable/ambiguous settings
fail closed without changing the Engine. This deliberately duplicates a narrow
guard rather than modifying/coupling to TeamService's private transaction boundary.
Engine initialization/test identity events may issue metadata reads before it;
trusted listeners must not mutate data or change connection mode.

Each transaction sets 5s lock/15s statement deadlines. Verification uses a READ ONLY
lookup, closes/commits that read transaction and releases the connection, then runs
real/dummy Argon2. CredentialService itself never updates hashes or creates sessions.
The returned public identity reflects that lookup/check, not a session lease or
issuance capability. M-007B.2B factors this same verification into a private record
path and snapshot for SessionService.login; public verify_credentials still returns
the original CredentialIdentity. SessionService rechecks identity, username,
timestamps and the verified hash fingerprint under locks before issuing. Future
password-change invalidation of already-issued sessions remains separate work.

| Condition | Fixed CredentialCode |
|---|---|
| Invalid registration input | invalid_input |
| 23505 + uq_credentials_username only | username_unavailable |
| Wrong/unknown/unsupported-hash credentials | invalid_credentials |
| Full KDF budget / native KDF failure | hashing_busy / hashing_failure |
| Unsupported transaction/logging configuration | transaction_configuration |
| 40P01 or 40001 | transaction_conflict, retryable |
| 55P03 | lock_timeout, retryable |
| 57014 | statement_timeout |
| Other class 23 / other DBAPI error | integrity_fault / database_failure |

Errors contain fixed codes/retryable only; no raw driver message or input. Mapping
runs after rollback/connection unwind, including COMMIT errors. Unexpected integrity
faults are not username conflicts. No retry loop. Connection loss during COMMIT can
be ambiguous; do not blindly retry. Registration availability is intentionally a
distinct conflict; future public abuse/enumeration policy/rate limits remain work.
